## 🎮 游戏机制实现

### 资源系统
```
基础产量：100/小时 (每种资源)
建筑加成：根据建筑类型和等级累加
计算公式：当前资源 = 上次资源 + (产量 × 经过秒数 / 3600)
上限保护：资源不超过仓库容量
```

### 建筑升级流程
1. 获取城市并更新资源
2. 查询目标建筑
3. 加载建筑配置
4. **检查前置条件** (如：兵营需要市政厅 3 级)
5. **计算升级成本** (基础成本 × (1 + 当前等级×0.3))
6. **验证资源充足**
7. 扣除资源
8. 提升建筑等级
9. 重新计算城市产量
10. 记录日志

### 建筑前置条件示例
- 金矿 → 需要农场 Lv.2
- 采石场 → 需要伐木场 Lv.2
- 铁矿 → 需要采石场 Lv.3 + 市政厅 Lv.5
- 兵营 → 需要市政厅 Lv.3
- 马厩 → 需要兵营 Lv.3 + 伐木场 Lv.4
- 工坊 → 需要铁矿 Lv.2 + 市政厅 Lv.7
- 学院 → 需要市政厅 Lv.4
- 城墙 → 需要市政厅 Lv.2
- 医院 → 需要市政厅 Lv.5

## 📊 技术亮点

1. **配置驱动设计**: 所有建筑数据集中在 BuildingConfig，易于平衡调整
2. **懒加载资源更新**: 不需要后台定时任务，访问时自动计算
3. **事务安全**: 所有资源操作在@Transactional 中保证一致性
4. **扩展性**: 新增建筑只需修改配置类，无需改动业务逻辑
5. **日志追踪**: 完整的操作日志便于调试和运营分析

## 🚀 使用方法

### 升级建筑示例
```bash
POST /api/city/building/upgrade
Content-Type: application/json
Authorization: Bearer {jwt_token}

{
  "cityId": 1,
  "buildingType": "FARM"
}
```

响应:
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 5,
    "type": "FARM",
    "level": 3,
    "posX": 2,
    "posY": 3
  }
}
```

### 错误处理
- 资源不足：返回 400 + "资源不足！需要：金币 XXX..."
- 前置条件不满足：返回 400 + "不满足建筑前置条件"
- 建筑不存在：返回 400 + "建筑不存在"
